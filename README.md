# Verbosity Bias in LLM Judges for Persian

Do LLMs that act as judges prefer **longer** answers, even when the extra length adds no information, or the long answer is wrong? This project measures that *verbosity bias* in a Persian, low-resource setting.

*Course research project for the graduate Large Language Models course at TEIAS (Spring 2025), by **Mohammad Ali Olama** and **Erfan Ahmadi** (equal contribution).*
Course repository: [maolama/LLM-Course-Spring2025](https://github.com/maolama/LLM-Course-Spring2025)

## Dataset

A new bilingual (English → Persian) benchmark of **367 prompts** across 10 task types:

| Category | # | Category | # |
|---|---|---|---|
| Factual | 39 | Creative Writing | 44 |
| Reasoning | 35 | Counter-factual | 43 |
| Opinion-based | 41 | Algorithm/Coding | 27 |
| Open-ended | 32 | STEM | 39 |
| Math | 39 | Extraction | 28 |

- **Sources:** prompts generated by LLMs (GPT-4, Gemini 2.5 Pro, Grok-3) and reviewed by hand, prompts adapted from MT-Bench, and prompts written by native Persian speakers.
- **Translation:** Gemini 2.5 Flash, followed by manual review for accuracy, fluency and cultural relevance (`codes/Translation.py`).
- **Responses:** Claude 3.7 Sonnet generates controlled Persian answer variants for each prompt (`codes/ResponseGeneration.py`):

  | Variant | Description |
  |---|---|
  | `short_correct` | short and correct |
  | `long_restricted` | long paraphrase of the short answer with **no new information** |
  | `long_unrestricted` | long, free to add examples and explanation |
  | `short_incorrect` / `long_incorrect` | subtly "poisoned" with realistic errors, with an explanation of each error |

- **Human labels:** a native Persian-speaking annotator marked the preferred answer (A, B or tie) to provide gold labels.

## Method

**Judges:** DeepSeek-R1 and Gemma 3 27B, accessed through OpenRouter. Each judge compares two answers using an MT-Bench-style prompt and outputs `[[A]]`, `[[B]]` or `[[C]]` (tie), along with a short justification (`codes/Evaluator.py`).

**Position bias control:** every pair is judged twice, with the answer order swapped the second time (`codes/utils/Evaluation_Aggregator.py`). The outcome falls into one of three cases:
- **Consistent:** the same answer wins in both orders.
- **Position-bias inconsistency:** the judge picks the same *slot* both times.
- **Unstable evaluation:** the judge picks an answer in one order and a tie in the other.

| Experiment | Comparison | Question it answers |
|---|---|---|
| 0 — Baseline | short vs. long (both unrestricted) | Do judges prefer length at all? |
| 1 — Information parity | short vs. long with **no extra information** | Is the preference for *length itself*? |
| 2 — Language variation | Experiment 0 with an **English** judge prompt | Does the prompt language matter? |
| 3 — Poisoning | correct short vs. **subtly wrong** long | Does length override correctness? (Algorithmic and Math only) |

Evaluations were run on the **Algorithmic, Math and Creative Writing** categories.

## Results

**Judge consistency across position swaps** (consistent / position-bias / unstable):

| Judge | Category | Exp 0 | Exp 1 | Exp 2 | Exp 3 |
|---|---|---|---|---|---|
| DeepSeek-R1 | Algorithmic | 27 / 0 / 0 | 19 / 6 / 2 | 27 / 0 / 0 | 21 / 5 / 1 |
| | Creative Writing | 40 / 2 / 0 | 35 / 7 / 0 | 40 / 2 / 0 | 40 / 2 / 0 |
| | Math | 28 / 9 / 2 | 27 / 5 / 7 | 33 / 6 / 0 | 32 / 7 / 0 |
| Gemma 3 27B | Algorithmic | 27 / 0 / 0 | 23 / 4 / 0 | 27 / 0 / 0 | 21 / 6 / 0 |
| | Creative Writing | 40 / 2 / 0 | 31 / 10 / 1 | 41 / 1 / 0 | 39 / 3 / 0 |
| | Math | 37 / 2 / 0 | 33 / 5 / 1 | 39 / 0 / 0 | 29 / 9 / 1 |

Creative Writing was the most stable category. Math produced the most position-bias inconsistencies, 27 of them for DeepSeek-R1.

**Agreement between the judges:** on comparisons where both judges were consistent, they agreed on **310 of 333 (≈93%)**. Most disagreements involved one judge being inconsistent rather than a direct A-vs-B conflict.

**Alignment with the human annotator:**
- **Baseline:** both judges strongly preferred the longer answer, even where the human preferred the short one or a tie. On Algorithmic tasks, both disagreed with the human in **21 of 27** cases. Gemma 3 disagreed **29** times on Math.
- **Information parity:** this experiment gave the strongest evidence of verbosity bias. The judges rewarded redundant length while the human preferred the concise answer: Gemma 3 disagreed **23** times on Math, and DeepSeek-R1 **21** times on Creative Writing.
- **Language variation:** switching the judging prompt to English did not remove the bias. Gemma 3 disagreed with the human **31** times on Math, and both judges disagreed **20+** times on Creative Writing. DeepSeek-R1 was more sensitive to the language switch: 8 Math items it had judged in Persian became inconsistent in English.
- **Poisoning:** this is where the judges differed most. **DeepSeek-R1** mostly rejected the long, incorrect answer and agreed with the human **28** times on Math. **Gemma 3** often preferred the poisoned long answer, disagreeing with the human **17** times on Algorithmic and **15** times on Math.

**Takeaways**
1. Verbosity bias is strong in both judges for Persian, and it persists when the extra length adds no information.
2. The bias does not depend on the prompt language: it remains with an English judging prompt.
3. DeepSeek-R1 can override its length preference when the long answer contains factual errors. Gemma 3 often cannot, which makes it an unreliable judge for fact-sensitive tasks.
4. Position bias and language sensitivity also affect verdicts, particularly for DeepSeek-R1 on Math.

## Repository Structure

```
Main.py                      # runs response generation and evaluation
codes/
  Translation.py             # EN → FA prompt translation (Gemini)
  ResponseGeneration.py      # controlled answer variants
  Evaluator.py               # pairwise judging experiments (both orders)
  GlobalVars.py              # generation and judge prompts
  Environment.py             # loads API settings from .env
  utils/                     # aggregation, consistency analysis, charts
data/
  questions/<category>/      # original + translated prompts
  responses/<model>/         # generated answer variants
  evaluation/<judge>/        # raw judge outputs and consistency labels
logs/                        # token and time usage
```

## Running
```bash
pip install -r requirements.txt
```
Create a `.env` file with `RESPONSE_GENERATION_MODEL`, `RESPONSE_GENERATION_API_URL` and `RESPONSE_GENERATION_API_KEY` (any OpenAI-compatible endpoint, e.g. OpenRouter). For translation, also add the `TRANSLATION_*` settings. Then:
```bash
python Main.py
```
